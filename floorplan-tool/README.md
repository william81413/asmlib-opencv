# Obergeschoss — 參數化格局工具

一個單檔網頁工具，用來調整這層樓的隔間位置、即時看到每個空間的面積變化、
自動檢核居住尺寸規則、估算施工成本量級，並比較不同方案。

直接用瀏覽器開 `index.html` 就能用，沒有建置步驟、沒有後端、不連外
（字型走 Google Fonts，離線時退回系統字型）。

```
floorplan-tool/
├── index.html              工具本體（介面英文）
└── extract/
    └── extract_plan.py     PDF → 牆體幾何的抽取管線（可重跑驗證）
```

介面是英文，但**圖面標註維持德式**（小數逗號、半公分上標 `3,56⁵`），房間名維持圖面德文
（Schlafen、Wohnen/Kochen/Essen…）—— 那是建築師的標籤，改掉就對不上圖了。

---

## 1. 幾何是怎麼來的

建築師的 `Obergeschoss.pdf` 是**向量圖不是掃描圖**，而且圖層依德國製圖慣例用顏色分類：

| 填色 | 意義 | 物件數 |
|---|---|---|
| 灰 `0.875` | Bestand 既有牆 | 45 |
| 紅 `0.961,0,0` | Neu 新建 | 31 |
| 黃 `1,1,0` | Abbruch 拆除 | 21 |

所以牆體可以直接從 PDF 的繪圖指令讀出來，**完全不需要影像辨識**。

```bash
pip install pymupdf
python3 extract/extract_plan.py Obergeschoss.pdf --check      # 自我驗證
python3 extract/extract_plan.py Obergeschoss.pdf > walls.json
python3 extract/extract_plan.py Obergeschoss.pdf --furniture  # 建築師家具的參考底圖
```

**不要在這裡加尺寸過濾器。** 早期版本用 `if w<7 and h<12: continue` 濾「尺寸線箭頭」，
結果把入戶門旁 24 × 22,9 cm 的門樘一起刪掉，整個東南角的模型因此建錯。
箭頭本來就落在 `BUILDING` 視窗之外，光靠視窗就夠了。

`--check` 會驗證兩件事：

1. 每道牆的厚度必須落在圖上標註的 24 / 17,5 / 11,5 cm；
2. 推導出的軸線必須重現圖上自己的尺寸鏈
   `24 + 3,56⁵ + 17⁵ + 3,98 + 24 + 2,31⁵ + 24 = 10,75⁵ m` — **目前 7/7 全數吻合**。

> PDF 本身含有業主姓名與住家地址，**沒有**收進這個公開 repo。
> 要重跑抽取請自己把檔案放到 `extract/` 底下。

## 2. 模型：軸線，不是座標

工具不存牆的座標，存的是**軸線**（`AX`，牆中心線，單位公尺，原點在擴建部分的西北角）。
每個房間的四個面都是「某軸線 ± 該牆厚度的一半」，所以移動一條軸線，
所有貼著它的房間會同時更新。這正是圖上尺寸鏈的做法。

```
xmid : 3,895 m  t=17,5 cm  承重   ← 中央承重牆，全樓深
y1   : 8,635 m  t=11,5 cm  輕隔間 ← 臥室／起居分界
y2   : 10,850 m t=11,5 cm  濕區   ← 玄關／衛浴分界
xbw  : 4,030 m  t=11,5 cm  輕隔間 ← 陽台／暖房隔間
xst  : 可選              新增   ← 切出儲藏室用
```

外牆（`lock:1`）不可動：9,70 × 10,80 的既有量體與北側擴建輪廓在這一版是固定的。

**固定障礙物**：兒童房東北角有一支既有磚砌煙囪（`x 3,285–3,793 × y 8,704–9,263`，
50,8 × 55,9 cm）。它吃掉 0,28 m²、擋家具，而且**中牆與臥室分界都不能穿過它** ——
中牆往西最多只能到 3,88 m（等於幾乎不能西移），臥室分界要嘛往北，要嘛一次跳到 9,32 以南。
工具會在牆走進煙囪時直接報錯。

軸線位置**吸附在圖面尺寸鏈的精確值**上，不是 PDF 的量測值 ——
從 PDF 抽出來會有 2–5 mm 的向量捨入誤差，吸附後為 0。

**尺寸鏈依德國製圖慣例標註**：淨尺寸與牆厚交替，未滿一米寫公分，
半公分寫上標 5（11,5 cm → `11⁵`）。工具畫出來的鏈與圖面逐段相同：

```
X  24 | 3,56⁵ | 17⁵ | 3,98 | 24 | 2,31⁵ | 24     = 10,75⁵
Y  24 | 5,09  | 11⁵ | 2,10 | 11⁵ | 2,90  | 24     = 10,80
```

這一點很重要：你要拿這張圖跟建築師討論，標註方式必須是他看得懂的那一套。
（早期版本畫的是外緣→牆中心線的距離，數字變成 5,38 / 2,21 / 3,20 ——
描述的是同一個幾何，但沒辦法跟圖面對照。）

**耦合**：`reconcile()` 保證共用牆的兩個房間不會同時被壓到最小值以下 ——
中牆東移到極限時，儲藏室隔間會被推著走，衛浴永遠保留 1,80 m 淨寬。

## 3. 家具

**你自己放，工具只檢查。** 但家具**不存絕對座標**，存的是相對於房間的錨點：

```js
{key:'bed_180', room:'schlafen', rot:0,
 snap:'n'|'s'|'e'|'w'|null,   // 貼哪一面牆，null = 自由擺放
 along, rx, ry}                // 沿牆比例 / 房間內相對位置
```

所以你動牆的時候家具**跟著走**，不會整組散掉。放不進去的物件會標紅並列進 findings，
**不會靜默消失**。

拖曳擺放，靠近牆 15 cm 內自動吸附；`R` 旋轉 90°、`Del` 刪除。
內建目錄有常見尺寸，每一件放進去之後都能個別改長寬，也可以加自訂矩形。

**真正的約束是淨距不是家具本體。** 每件家具帶方向性淨距，跟著旋轉：

| 家具 | 淨距 |
|---|---|
| 雙人床 1,80 × 2,00 | 床尾 0,70、兩側 0,75 / 0,55 |
| 單人床 0,90 × 2,00 | 床尾 0,70、單側 0,70 |
| 衣櫃（深 0,60） | 開門 0,65 |
| 書桌 1,40 × 0,70 | 前方 0,80 |
| 沙發 2,40 × 0,95 | 前方 0,90 |
| 餐桌 1,60 × 0,90 | 四周各 0,80（拉椅） |

檢查項目：本體重疊、淨距被別人的本體佔用、超出房間、撞煙囪、站在門弧裡、
擋住通道開口（0,60）、高櫃擋窗（0,20）。訊息具體到公分，例如
`clearance to Double bed short by 15 cm`。

適用房間：Schlafen、Kind、Wohnen/Kochen/Essen。
**廚房與衛浴設備不做擺放** —— 位置幾乎被既有管道決定，維持尺寸門檻檢查。

`Sheet furniture` 可以疊出建築師原案畫的家具當參考（從 PDF 的黑色線段抽出，277 段）。
它是**原始牆位**下的配置，所以任何牆一移動就自動變淡並標註。

## 4. 門

門的位置是**狀態不是常數**，可以沿牆拖曳 —— 因為門開在哪直接決定家具怎麼放。
夾限：留在它服務的房間範圍內、兩端各留 0,10 m 門樘。鉸鏈側與開啟方向可切換。
**門弧是家具檢查的障礙物。**

窗維持不可動（動窗屬於外牆改造，超出目前範圍）。

## 5. Undo / Redo

`Ctrl/Cmd+Z` 與 `Ctrl/Cmd+Shift+Z`，或標題列的 ↩ ↪。
狀態含軸線、儲藏室開關、門、家具，上限 50 步。拖曳結束才記錄一筆，不是拖曳過程中每一格。

## 6. 規則檢核（自住權重）

每一條規則都是可查證的淨尺寸，寫在 `RULES`，訊息裡直接寫出門檻值：

| 空間 | 硬門檻 | 建議值 |
|---|---|---|
| 主臥 | 淨寬 ≥ 2,80 m、面積 ≥ 12 m² | 淨寬 ≥ 3,10 m |
| | 1,80×2,00 床 + 兩側 0,75 / 0,55 + 床尾 0,70 | 衣櫃牆面 ≥ 2,00 m |
| 兒童房 | 淨寬 ≥ 2,40 m、面積 ≥ 10 m² | |
| 起居／廚房／餐廳 | 淨寬 ≥ 3,60 m、面積 ≥ 22 m² | 淨寬 ≥ 4,00 m |
| 玄關 | 淨寬 ≥ 1,10 m | ≥ 1,30 m（放得下鞋櫃） |
| 衛浴 | 淨寬 ≥ 1,75 m（浴缸 1,70）、面積 ≥ 5,5 m² | 6,5–9,0 m² |
| 儲藏 | 淨寬 ≥ 0,90 m、面積 ≥ 1,5 m² | ≥ 2,0 m² |
| 陽台 | 進深 ≥ 1,50 m | 面積 ≥ 6 m² |

評分是 5 個維度的加權和，權重寫死在 `score()` 裡好讓人吵：
Programme 30 / Furniture 25 / Budget 20 / Circulation 15 / Storage 10。

**Furniture 這一項現在是真的量出來的** —— 必要家具中「已放置且無衝突」的比例，
再依衝突件數扣分。舊版是 `1 − 壞findings數/5`，跟 Programme 重複計算同一批 findings，
已經修掉。

**這組權重是起點不是答案。** 建議的用法：先自己手排幾個方案，
看評分排序跟你的直覺是否一致，不一致就改權重 —— 而不是反過來相信分數。

成本是量級估算，不是報價：輕隔間 €380/m、承重牆 €6.500 + €900/m（含過樑與結構計算）、
排水改道 €2.500 + €450/m。

## 7. 面積怎麼算的（重要）

**圖上印的 NGF 就是基準。** PDF 的房間標註本身是文字，直接讀得到，所以原始格局**不需要**用算的 ——
工具一打開顯示的就是圖面上的 `17,60` / `27,06` / `10,63`，逐項完全相同。

幾何只負責提供「差多少」：

```
顯示面積 = 圖面 NGF + (現在的幾何面積 − 原始的幾何面積)
```

沒動牆 → 括號為 0 → 跟 PDF 一致。中牆東移 40 cm → Schlafen 顯示 `17,60 + 2,05 = 19,65`。
這樣下面那筆來源不明的落差就被吸收在基準裡，不會干擾你讀數字。

面積卡片右上角的按鈕可以切到**純幾何面積**，看未校正的原始值 —— 跟建築師對帳時用。

**這個做法的前提**：假設扣除量在你調整牆體時維持不變（絕對值）。如果落差真的來自西牆內襯，
那它其實會隨著房間長度變動 —— 但在合理的調整幅度內差異小於 0,05 m²，先這樣。

**幾何面積 vs 建築師 NGF**（切到純幾何模式時看到的）：

| 空間 | 幾何 | 標註 NGF | 差 |
|---|---|---|---|
| Wintergarten | 15,02 | 14,99 | +0,03 |
| Diele | 8,35 | 8,32 | +0,03 |
| Balkon（½） | 5,14 | 5,13 | +0,01 |
| Schlafen | 18,15 | 17,60 | **+0,55** |
| Kind | 18,24 | 17,40 | **+0,84** |
| Wohnen/Kochen/Essen | 27,87 | 27,06 | **+0,81** |
| Bad/WC | 11,52 | 10,63 | **+0,89** |

前三項吻合到公分，後四項各多 0,55–0,89 m²（合計約 3 m²）。
四個有落差的空間都貼著 17,5 cm 中牆或既有外牆，推測是管道間或牆面內襯的扣除，
**但這要跟建築師確認** —— 如果是內襯，那所有房間的可用淨寬都要再減。

**「Balkon 1/2」** 的 5,13 m² 是實際 10,27 m² 依 WoFlV 計 ½ 的結果，工具照此顯示。

**模型的東南角**：住戶東界在起居室以下從 9,46 退到 7,96；玄關那一段的既有東外牆
（`ABBRUCH 9.457 8.691 9.699 10.791`，正好 2,100 m）是**要拆掉**的，新樓梯間就是這樣接進室內。
入戶門在 `x 7,96–8,20` 的新牆上，開口 `y 8,920–9,927`（1,007 m）。
樓梯間整塊鎖定、不列入住戶面積。

**沒有任何淨高資料** —— 如果臥室上方是斜屋頂，家具檢查會**系統性偏樂觀**：
2,00 m 高的衣櫃在平面上放得下，但淨高 1,40 m 的地方根本立不起來。
工具會給綠燈。這是目前最大的未知數，需要 A–A 剖面圖。

**還沒進模型的**：
- 屋頂斜度 / Kniestock 高度 → 影響 Wohnfläche 與 LBO BW 的 2,30 m 淨高要求
- 管道立管實際位置 → 目前只把 `y2` 標為「濕區」加成本，沒有真的做管線路徑
- Wintergarten 是否為暖房 → 影響 GEG 與是否計入居住面積
- Baulinie 超線的 Befreiung → 若未核准，北側擴建 20 m² 會消失，需要無擴建的備案

## 8. 下一步

- 淨高／Kniestock 進模型（**最優先**，會影響所有結論）
- 採光規則（居室窗面積 ≥ 房間面積 1/8）
- 成本模型改用實際受影響牆長，不是固定的 10,3 / 5,5 m
- 新增／刪除隔間（例如把兒童房一分為二）—— 目前拓樸是鎖死的
- 匯入 JSON、匯出圖面（PNG/PDF/DXF）給建築師

**不建議先做自動優化器。** 評分函數沒有校準過的話，優化器只會很有效率地產生垃圾。
先把評分器餵到跟你的直覺一致，再談自動生成。
