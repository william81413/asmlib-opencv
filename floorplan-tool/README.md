# Obergeschoss — 參數化格局工具

一個單檔網頁工具，用來調整這層樓的隔間位置、即時看到每個空間的面積變化、
自動檢核居住尺寸規則、估算施工成本量級，並比較不同方案。

直接用瀏覽器開 `index.html` 就能用，沒有建置步驟、沒有後端、不連外
（字型走 Google Fonts，離線時退回系統字型）。

```
floorplan-tool/
├── index.html              工具本體
└── extract/
    └── extract_plan.py     PDF → 牆體幾何的抽取管線（可重跑驗證）
```

---

## 1. 幾何是怎麼來的

建築師的 `Obergeschoss.pdf` 是**向量圖不是掃描圖**，而且圖層依德國製圖慣例用顏色分類：

| 填色 | 意義 | 物件數 |
|---|---|---|
| 灰 `0.875` | Bestand 既有牆 | 45 |
| 紅 `0.961,0,0` | Neu 新建 | 31 |
| 黃 `1,1,0` | Abbruch 拆除 | 21 |

所以牆體可以直接從 PDF 的繪圖指令讀出來，**完全不需要影像辨識**。

```bash
pip install pymupdf
python3 extract/extract_plan.py Obergeschoss.pdf --check   # 自我驗證
python3 extract/extract_plan.py Obergeschoss.pdf > walls.json
```

`--check` 會驗證兩件事：

1. 每道牆的厚度必須落在圖上標註的 24 / 17,5 / 11,5 cm；
2. 推導出的軸線必須重現圖上自己的尺寸鏈
   `24 + 3,56⁵ + 17⁵ + 3,98 + 24 + 2,31⁵ + 24 = 10,75⁵ m` — **目前 7/7 全數吻合**。

> PDF 本身含有業主姓名與住家地址，**沒有**收進這個公開 repo。
> 要重跑抽取請自己把檔案放到 `extract/` 底下。

## 2. 模型：軸線，不是座標

工具不存牆的座標，存的是**軸線**（`AX`，牆中心線，單位公尺，原點在擴建部分的西北角）。
每個房間的四個面都是「某軸線 ± 該牆厚度的一半」，所以移動一條軸線，
所有貼著它的房間會同時更新。這正是圖上尺寸鏈的做法。

```
xmid : 3,895 m  t=17,5 cm  承重   ← 中央承重牆，全樓深
y1   : 8,635 m  t=11,5 cm  輕隔間 ← 臥室／起居分界
y2   : 10,850 m t=11,5 cm  濕區   ← 玄關／衛浴分界
xbw  : 4,030 m  t=11,5 cm  輕隔間 ← 陽台／暖房隔間
xst  : 可選              新增   ← 切出儲藏室用
```

外牆（`lock:1`）不可動：9,70 × 10,80 的既有量體與北側擴建輪廓在這一版是固定的。

軸線位置**吸附在圖面尺寸鏈的精確值**上，不是 PDF 的量測值 ——
從 PDF 抽出來會有 2–5 mm 的向量捨入誤差，吸附後為 0。

**尺寸鏈依德國製圖慣例標註**：淨尺寸與牆厚交替，未滿一米寫公分，
半公分寫上標 5（11,5 cm → `11⁵`）。工具畫出來的鏈與圖面逐段相同：

```
X  24 | 3,56⁵ | 17⁵ | 3,98 | 24 | 2,31⁵ | 24     = 10,75⁵
Y  24 | 5,09  | 11⁵ | 2,10 | 11⁵ | 2,90  | 24     = 10,80
```

這一點很重要：你要拿這張圖跟建築師討論，標註方式必須是他看得懂的那一套。
（早期版本畫的是外緣→牆中心線的距離，數字變成 5,38 / 2,21 / 3,20 ——
描述的是同一個幾何，但沒辦法跟圖面對照。）

**耦合**：`reconcile()` 保證共用牆的兩個房間不會同時被壓到最小值以下 ——
中牆東移到極限時，儲藏室隔間會被推著走，衛浴永遠保留 1,80 m 淨寬。

## 3. 規則檢核（自住權重）

每一條規則都是可查證的淨尺寸，寫在 `RULES`，訊息裡直接寫出門檻值：

| 空間 | 硬門檻 | 建議值 |
|---|---|---|
| 主臥 | 淨寬 ≥ 2,80 m、面積 ≥ 12 m² | 淨寬 ≥ 3,10 m |
| | 1,80×2,00 床 + 兩側 0,75 / 0,55 + 床尾 0,70 | 衣櫃牆面 ≥ 2,00 m |
| 兒童房 | 淨寬 ≥ 2,40 m、面積 ≥ 10 m² | |
| 起居／廚房／餐廳 | 淨寬 ≥ 3,60 m、面積 ≥ 22 m² | 淨寬 ≥ 4,00 m |
| 玄關 | 淨寬 ≥ 1,10 m | ≥ 1,30 m（放得下鞋櫃） |
| 衛浴 | 淨寬 ≥ 1,75 m（浴缸 1,70）、面積 ≥ 5,5 m² | 6,5–9,0 m² |
| 儲藏 | 淨寬 ≥ 0,90 m、面積 ≥ 1,5 m² | ≥ 2,0 m² |
| 陽台 | 進深 ≥ 1,50 m | 面積 ≥ 6 m² |

評分是 5 個維度的加權和，權重寫死在 `score()` 裡好讓人吵：
面積達標 30 / 家具可行 25 / 成本 20 / 交通效率 15 / 收納 10。

**這組權重是起點不是答案。** 建議的用法：先自己手排幾個方案，
看評分排序跟你的直覺是否一致，不一致就改權重 —— 而不是反過來相信分數。

成本是量級估算，不是報價：輕隔間 €380/m、承重牆 €6.500 + €900/m（含過樑與結構計算）、
排水改道 €2.500 + €450/m。

## 4. 已知的落差與待確認事項

**幾何面積 vs 建築師 NGF**：工具顯示的是幾何淨面積。與圖上標註的 NGF 有系統性落差：

| 空間 | 幾何 | 標註 NGF | 差 |
|---|---|---|---|
| Wintergarten | 15,02 | 14,99 | +0,03 |
| Diele | 8,35 | 8,32 | +0,03 |
| Balkon（½） | 5,14 | 5,13 | +0,01 |
| Schlafen | 18,15 | 17,60 | **+0,55** |
| Kind | 18,24 | 17,40 | **+0,84** |
| Wohnen/Kochen/Essen | 27,87 | 27,06 | **+0,81** |
| Bad/WC | 11,52 | 10,63 | **+0,89** |

前三項吻合到公分，後四項各多 0,55–0,89 m²（合計約 3 m²）。
四個有落差的空間都貼著 17,5 cm 中牆或既有外牆，推測是管道間或牆面內襯的扣除，
**但這要跟建築師確認** —— 如果是內襯，那所有房間的可用淨寬都要再減。

**「Balkon 1/2」** 的 5,13 m² 是實際 10,27 m² 依 WoFlV 計 ½ 的結果，工具照此顯示。

**還沒進模型的**：
- 屋頂斜度 / Kniestock 高度 → 影響 Wohnfläche 與 LBO BW 的 2,30 m 淨高要求
- 管道立管實際位置 → 目前只把 `y2` 標為「濕區」加成本，沒有真的做管線路徑
- Wintergarten 是否為暖房 → 影響 GEG 與是否計入居住面積
- Baulinie 超線的 Befreiung → 若未核准，北側擴建 20 m² 會消失，需要無擴建的備案
